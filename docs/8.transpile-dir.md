---
title: Transpiling a Directory
description: Use the `transpileDir` rolldown plugin to transpile a directory file by file in any tsdown or rolldown build.
---

`builder()` transpiles the runtime directory with a rolldown plugin, `transpileDir`, which `@nuxt/module-builder/rolldown` exports. Use it in any tsdown or rolldown build that transpiles a directory file by file instead of bundling it, such as a library that isn't a Nuxt module:

```ts [tsdown.config.ts]
import { defineConfig } from 'tsdown'
import { transpileDir } from '@nuxt/module-builder/rolldown'

export default defineConfig({
  entry: ['src/index.ts'],
  plugins: [
    transpileDir({ srcDir: 'src/runtime', outBase: 'runtime' }),
  ],
})
```

The plugin emits every file under `srcDir` under `outBase` in the build's output directory. It keeps each file's name, apart from the extension:

- Scripts become `.js`, or `.mjs` with `extension: 'mjs'`.
- `.tsx` and `.jsx` files become `.jsx`, with their JSX kept.
- Sass files compile to `.css`.
- Test and story files are left out by default.

Scripts are transpiled with oxc, and keep their imports as written. Relative imports are the exception: they get the emitted extension. `.vue` files are transpiled with `vue-sfc-transformer`, stylesheets are processed as described in [Build Output](/docs/guide/modules/module-builder/output#runtime-files), and other files are copied. Declarations come from one TypeScript program per tsconfig project: the nearest `tsconfig.json`, or the project in its `references` that includes the file.

By default, the plugin transpiles scripts with the `transform` from `rolldown/utils`. `rolldown` is an optional peer dependency of `@nuxt/module-builder`, so install it in your project, or pass a `transform` of your own. `builder()` passes the `transform` of the `rolldown` that `tsdown` installs, so a module that builds with `builder()` needs neither.

## Options

| Option | Default | Description |
|---|---|---|
| `srcDir` | | The directory whose files are transpiled one by one. |
| `outBase` | the output directory | Where the outputs go, relative to the build's output directory. |
| `cwd` | the build's `cwd` | The project root: where `srcDir` is resolved, the tsconfig search starts, and `node_modules` is read. |
| `include` | every file | Globs of files to include, relative to `srcDir`. |
| `exclude` | test and story files | Globs of files to exclude. |
| `extension` | `'js'` | The extension of emitted scripts: `'js'` or `'mjs'`. Declarations follow, as `.d.ts` or `.d.mts`. |
| `tsconfig` | the nearest above `cwd` | The tsconfig to compile with, or `false` for none. |
| `paths` | | `paths` added to the tsconfig's when generating declarations. |
| `jsx` | `'preserve'` | JSX compilation for `.tsx` and `.jsx` files, or a function of the source path that returns it. `'preserve'` emits them as `.jsx` with types stripped, next to a `.d.ts`. |
| `transform` | the one of the installed `rolldown` | The oxc `transform` to use. |
| `sourcemap` | `false` | Emit source maps next to scripts. |
| `declaration` | `true` | Generate declarations. |
| `stylesheets` | `true` | Process `.css` with lightningcss and compile Sass. `false` copies stylesheets as they are. |
| `vue` | enabled | Options for `.vue` files, or `false` to leave them out. |
| `resolveExternal` | | Decides what happens to relative imports that resolve outside `srcDir`. |

The options are documented in full on the `TranspileDirOptions` type.

## Imports outside `srcDir`

By default, the plugin keeps a relative import that resolves outside `srcDir` as written. To change that, pass `resolveExternal`, which the plugin calls for each such import. Its third argument describes the import:

- `file`: the absolute path of the imported file.
- `kind`: `'value'`, or `'type'` for an import that's only used for its type.
- `from` and `output`: the paths where the importer and the imported file would be emitted.

`resolveExternal` returns one of these values:

- A string: the specifier to write instead.
- `{ mirror: 'value' }` or `{ mirror: 'type' }`: emit the file alongside the directory, as a script and a declaration, or as a declaration only. An `output` path, relative to the output directory, overrides where the file goes.
- `undefined`: keep the specifier as written.

This config emits every imported file outside `srcDir` next to the directory:

```ts [tsdown.config.ts]
import { defineConfig } from 'tsdown'
import { transpileDir } from '@nuxt/module-builder/rolldown'

export default defineConfig({
  entry: ['src/index.ts'],
  plugins: [
    transpileDir({
      srcDir: 'src/runtime',
      outBase: 'runtime',
      resolveExternal: (_specifier, _importer, { kind }) => ({ mirror: kind }),
    }),
  ],
})
```

## A build with nothing to bundle

A build that only transpiles directories can pass `emptyEntry`, from the same export, as its `entry`. `transpileDir` removes its chunk from the output:

```ts [tsdown.config.ts]
import { defineConfig } from 'tsdown'
import { emptyEntry, transpileDir } from '@nuxt/module-builder/rolldown'

export default defineConfig({
  entry: emptyEntry,
  plugins: [
    transpileDir({ srcDir: 'src' }),
  ],
})
```

## Type errors

Errors that would leave a declaration missing or wrong fail the build. The plugin reports other type errors as one warning per directory. The warning's `pluginCode` equals the `TYPE_ERRORS_WARNING` constant from `@nuxt/module-builder/rolldown`. An `onLog` handler can then filter the warning, or turn it into an error:

```ts [tsdown.config.ts]
import { defineConfig } from 'tsdown'
import { transpileDir, TYPE_ERRORS_WARNING } from '@nuxt/module-builder/rolldown'

export default defineConfig({
  entry: ['src/index.ts'],
  inputOptions: {
    onLog(level, log, handler) {
      handler(log.pluginCode === TYPE_ERRORS_WARNING ? 'error' : level, log)
    },
  },
  plugins: [
    transpileDir({ srcDir: 'src/runtime', outBase: 'runtime' }),
  ],
})
```
