---
title: Transpiling a Directory
description: Use the `transpileDir` rolldown plugin to transpile a directory file by file in any tsdown or rolldown build.
---

The runtime build is a rolldown plugin, `transpileDir`, exported from `@nuxt/module-builder/rolldown`. Use it in any tsdown or rolldown build that transpiles a directory file by file instead of bundling it:

```ts [tsdown.config.ts]
import { defineConfig } from 'tsdown'
import { transpileDir } from '@nuxt/module-builder/rolldown'

export default defineConfig({
  entry: ['src/index.ts'],
  plugins: [
    transpileDir({ srcDir: 'src/runtime', outBase: 'runtime' }),
  ],
})
```

Every file under `srcDir` is emitted under `outBase` in the build's output directory, with its name intact apart from the extension. Scripts become `.js` (or `.mjs`), `.tsx` and `.jsx` files become `.jsx` while their JSX is preserved, and compiled Sass becomes `.css`. Test and story files are excluded by default.

Scripts are transpiled with oxc and keep their imports as written, apart from relative imports, which get the emitted extension. `.vue` files are transpiled with `vue-sfc-transformer`, stylesheets are processed as described in [Build output](/docs/guide/modules/module-builder/output#runtime-files), and other files are copied. Declarations come from one TypeScript program that uses the nearest `tsconfig.json`.

By default, scripts are transpiled with the `transform` from `rolldown/utils`. `rolldown` is an optional peer dependency of `@nuxt/module-builder`, so install it in your project, or pass a `transform` of your own. `nuxt-module-build build` passes the `transform` of the `rolldown` that `tsdown` installs, so a module needs neither.

## Options

| Option | Default | Description |
|---|---|---|
| `srcDir` | | The directory whose files are transpiled one by one. |
| `outBase` | the output directory | Where the outputs go, relative to the build's output directory. |
| `cwd` | the build's `cwd` | The project root: where `srcDir` is resolved, the tsconfig search starts, and `node_modules` is read. |
| `include` | every file | Globs of files to include, relative to `srcDir`. |
| `exclude` | test and story files | Globs of files to exclude. |
| `extension` | `'js'` | The extension of emitted scripts: `'js'` or `'mjs'`. Declarations follow, as `.d.ts` or `.d.mts`. |
| `tsconfig` | the nearest above `cwd` | The tsconfig to compile with, or `false` for none. |
| `paths` | | `paths` added to the tsconfig's when generating declarations. |
| `jsx` | `'preserve'` | JSX compilation for `.tsx` and `.jsx` files, or a function of the source path that returns it. `'preserve'` emits them as `.jsx` with types stripped, next to a `.d.ts`. |
| `transform` | the one of the installed `rolldown` | The oxc `transform` to use. |
| `sourcemap` | `false` | Emit source maps next to scripts. |
| `declaration` | `true` | Generate declarations. |
| `stylesheets` | `true` | Process `.css` with lightningcss and compile Sass. `false` copies stylesheets as they are. |
| `vue` | enabled | Options for `.vue` files, or `false` to leave them out. |
| `resolveExternal` | | Decides what happens to relative imports that resolve outside `srcDir`. |

The options are documented in full on the `TranspileDirOptions` type.

## Imports outside `srcDir`

By default, a relative import that resolves outside `srcDir` is kept as written. `resolveExternal` is called for each one. Its third argument describes the import: the absolute path of the file, and whether the import is for its value or only its type. It also gives the paths where the importer and the file would be emitted. It returns one of:

- A string: the specifier to write instead.
- `{ mirror: 'value' }` or `{ mirror: 'type' }`: emit the file alongside the directory, as a script and declaration, or as a declaration only. An `output` path, relative to the output directory, overrides where it's emitted.
- `undefined`: keep the specifier as written.

```ts [tsdown.config.ts]
transpileDir({
  srcDir: 'src/runtime',
  outBase: 'runtime',
  resolveExternal: (_specifier, _importer, { kind }) => ({ mirror: kind }),
})
```

## A build with nothing to bundle

A build that only transpiles directories can pass `emptyEntry`, from the same export, as its `entry`. `transpileDir` removes its chunk from the output:

```ts [tsdown.config.ts]
import { defineConfig } from 'tsdown'
import { emptyEntry, transpileDir } from '@nuxt/module-builder/rolldown'

export default defineConfig({
  entry: emptyEntry,
  plugins: [
    transpileDir({ srcDir: 'src' }),
  ],
})
```

## Type errors

Errors that would leave a declaration missing or wrong fail the build. Other type errors are reported as one warning per directory. Its `pluginCode` equals the `TYPE_ERRORS_WARNING` constant, exported from `@nuxt/module-builder/rolldown`, so an `onLog` handler can filter the warning or turn it into an error.
