---
title: Configuration
description: Build entries other than `src/module.ts`, keep packages external, and the deprecated `build.config.ts`.
---

A module with `src/module.ts` and `src/runtime/` needs no configuration. To build other files, list them in the `build.entries` field of `package.json`:

```json [package.json]
{
  "build": {
    "entries": [
      "./src/utils",
      { "input": "./src/kit/index", "name": "kit" },
      { "input": "src/features/", "outDir": "dist/features", "ext": "js" }
    ]
  }
}
```

An entry is either bundled, like `src/module.ts`, or a directory transpiled file by file, like `src/runtime/`.

## Bundled entries

A string, or an object with `input` and an optional `name`, is bundled with tsdown into a single file:

| Option | Description |
|---|---|
| `input` | The entry file, relative to the module root. The extension can be left out. |
| `name` | The output name. Defaults to `input` without `src/` and without its extension. |

Each bundled entry is written to `dist/<name>.mjs`, with its declarations in `dist/<name>.d.mts`. The entries above produce `dist/utils.mjs` and `dist/kit.mjs`. Add each one to the `exports` of `package.json`, as described in [Exports](/docs/guide/modules/module-builder/exports#bundled-entries).

Bundled entries share the module entry's externals. These are never bundled:

- `@nuxt/kit`, `@nuxt/schema`, `nuxt`, `vue`, and the `#app`, `#build`, and `#imports` aliases.
- Your module's own package name, and the `#` subpath imports in the `imports` field of `package.json`.
- `dependencies`, `peerDependencies`, and `optionalDependencies`.
- The packages in `build.externals`.

Any other package an entry imports, such as a `devDependency`, is bundled into it.

## Externals

To keep a package that isn't a dependency out of the bundled entries, list it in the `build.externals` field of `package.json`. Each name also covers its subpaths, so `shiki` keeps `shiki/core` external too:

```json [package.json]
{
  "build": {
    "externals": ["shiki"]
  }
}
```

The import is then kept as written, and resolves in the app that installs the module.

## Directory entries

An object whose `input` ends in `/` is a directory. Every file in it is transpiled on its own, in the same way as `src/runtime/`:

| Option | Description |
|---|---|
| `input` | The source directory, relative to the module root, ending in `/`. |
| `outDir` | The output directory. Defaults to `dist`. It must be inside `dist`. |
| `ext` | The extension of emitted scripts: `mjs` (the default) or `js`. Declarations use the matching `.d.mts` or `.d.ts`. |

The entry above writes the files of `src/features/` to `dist/features/`, with `.js` scripts and `.d.ts` declarations. See [Build output](/docs/guide/modules/module-builder/output#runtime-files) for how each kind of file is emitted.

Files in a directory entry follow the rules of the runtime directory. Their relative imports can leave out the extension, and module code that imports them points at their output instead of bundling them.

## `build.config.ts`

`build.config.ts` (or `.mts`, `.js`, `.mjs`) and the `unbuild` field of `package.json` are deprecated. The build reads them, warns, and still applies these options:

- `entries`, in the shapes described above.
- `externals`: package names, as in [`build.externals`](#externals), and regular expressions.
- `replace` and `rollup.replace`: compile-time replacements in the bundled entries.
- `sourcemap`: `true` emits source maps, like `--sourcemap`.
- The `build:before`, `rollup:done`, and `build:done` hooks.

`mkdist:*` hooks are ignored with a warning, and a few other options are accepted at their defaults. Any other option fails the build, with a list of each one and the file it comes from. To type the file, import `defineBuildConfig` from `@nuxt/module-builder`:

```ts [build.config.ts]
import { defineBuildConfig } from '@nuxt/module-builder'

export default defineBuildConfig({
  hooks: {
    'build:done'(ctx) {
      console.log(`Built ${ctx.options.name} into ${ctx.options.outDir}`)
    },
  },
})
```

Move `entries` and string `externals` to the `build` field of `package.json`, and delete the file once nothing else is left in it. See [Build configuration](/docs/guide/modules/module-builder/upgrade-v2#build-configuration) in the upgrade guide for how each option is applied, and for the options that fail the build.
