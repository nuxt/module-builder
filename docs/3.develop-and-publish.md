The [module starter](https://github.com/nuxt/starter/tree/module) has a script for each stage of a module's life: preparing a fresh checkout, running the playground, and publishing a release. This page describes what each one does. To create a module from the starter, see [Getting Started](/docs/guide/modules/module-builder).

## Preparing a checkout

The starter's `dev:prepare` script runs all three steps that a fresh checkout needs:

```json [package.json]
{
  "scripts": {
    "dev": "npm run dev:prepare && nuxt dev playground",
    "dev:prepare": "nuxt-module-build build --stub && nuxt-module-build prepare && nuxt prepare playground",
    "prepack": "nuxt-module-build build"
  }
}
```

1. `nuxt-module-build build --stub` points `dist` at your sources. See [`build --stub`](/docs/guide/modules/module-builder/commands#build-stub).
2. `nuxt-module-build prepare` generates the module's own `.nuxt`, for the module's `tsconfig.json`. See [`prepare`](/docs/guide/modules/module-builder/commands#prepare).
3. `nuxt prepare playground` generates the playground's `.nuxt`. The playground installs the module by its package name, so this step loads the stub from step 1.

Run `dev:prepare` after you install dependencies, and again when the types it generates are out of date. `build` runs `prepare` on its own when `.nuxt` is missing. Keeping `prepare` in `dev:prepare` puts the module's types in place before your editor or type check needs them.

## Working in the playground

The [playground](/docs/guide/modules/module-builder/project-structure#playground) is a Nuxt app that installs your module, so you can try it out as you change it:

- `npm run dev` prepares the checkout and starts the playground's development server. It reloads as you change files in `src/`.
- `npm run dev:build` builds the playground with `nuxt build playground`.
- Any other `nuxt` command works against the playground too, as `nuxt <command> playground`.

The playground loads the module from `dist`. After a stub build, `dist` re-exports your sources. To try the output you publish instead, build the module and start the playground directly:

```bash
npx nuxt-module-build build && npx nuxt dev playground
```

`npm run dev` runs `dev:prepare` first, which replaces the build with the stub again. Run `dev:prepare` when you want to go back to the stub.

The starter also has `lint`, `test`, and `test:types` scripts. See [Testing](/docs/guide/modules/testing) in the Module Author Guide for the tests themselves.

## Publishing

The `prepack` script runs `nuxt-module-build build`, so the package manager builds the module whenever it packs or publishes it. You don't need to build it yourself first.

Before your first release, create an account on [npmjs.com](https://www.npmjs.com) and log in with `npm login`. To check the package before you publish it, run [publint](https://publint.dev) in the module root. Then pack the module and run [Are the Types Wrong?](https://arethetypeswrong.github.io) on the tarball:

```bash
npx publint
npm pack
npx @arethetypeswrong/cli ./my-module-1.0.0.tgz
```

The starter's `release` script publishes a new version:

```json [package.json]
{
  "scripts": {
    "release": "npm run lint && npm run test && npm run prepack && changelogen --release && npm publish && git push --follow-tags"
  }
}
```

1. It runs the linter, the tests, and the build. The release stops if any of them fails.
2. `changelogen --release` bumps the version, updates `CHANGELOG.md` from your commit messages, and commits and tags the result.
3. `npm publish` publishes the package. `prepack` builds the module again, so `dist` has the new version.
4. `git push --follow-tags` pushes the release commit and its tag.

Commit your changes before you run `release`. `changelogen` reads [Conventional Commits](https://www.conventionalcommits.org) to choose the version bump and to write the changelog.
