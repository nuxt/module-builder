A module builds with `tsdown`, through the [`builder()` plugin](/docs/guide/modules/module-builder/configuration) in its `tsdown.config.ts`. `@nuxt/module-builder` also installs the `nuxt-module-build` command, which has two subcommands: `build` and `prepare`. Name the subcommand every time: `nuxt-module-build` without one runs `build` and prints a warning.

The Nuxt CLI runs the same commands as [`nuxt build-module`](/docs/api/commands/build-module): `nuxt build-module build` is `nuxt-module-build build`. To see how a module's scripts combine them, read [Develop and Publish](/docs/guide/modules/module-builder/develop-and-publish).

## `tsdown`

```bash [Terminal]
npx tsdown [--outDir=<directory>] [--sourcemap] [--watch]
```

Builds the module for publishing with its `tsdown.config.ts`. This is the command that the `prepack` script runs:

```json [package.json]
{
  "scripts": {
    "prepack": "tsdown"
  }
}
```

`tsdown` needs a `tsdown.config.ts` that uses `builder()`. Without one, it doesn't build the module. The build runs the steps described in [`build`](#build), and tsdown's own options, such as `--outDir` and `--sourcemap`, take precedence over the config.

`tsdown --watch` builds the module, then rebuilds it when a source file changes, including the files that `src/module.ts` imports and files added to the runtime directory. It leaves the output directory in place while its first build runs. A rebuild only writes the files whose content changed, and removes the files that the build no longer emits. See [Developing against `dist`](/docs/guide/modules/module-builder/develop-and-publish#developing-against-dist).

## `build`

```bash [Terminal]
npx nuxt-module-build build [ROOTDIR] [--cwd=<directory>] [--outDir=<directory>] [--sourcemap]
```

Builds the module for publishing, with the same output, checks, and warnings as `tsdown`. With a `tsdown.config.ts`, it builds with that config. Without one, it builds `src/module.ts` and `src/runtime/`, plus the entries in the [`build` field of `package.json`](/docs/guide/modules/module-builder/configuration#without-a-tsdown-config), so a module needs no configuration file.

Both commands run these steps:

1. It checks the paths that `package.json` publishes, with the fields of `publishConfig` in place of the top-level ones. When it runs as the `prepack` or `prepublishOnly` script, it also checks that the package manager that packs applies `publishConfig`. See [Checks on published paths](/docs/guide/modules/module-builder/develop-and-publish#checks-on-published-paths).
2. If `.nuxt/tsconfig.json` is missing from the module root, it runs [`prepare`](#prepare) first.
3. It reads the [build configuration](/docs/guide/modules/module-builder/configuration) and checks that the module code loads with Node. See [Module code](/docs/guide/modules/module-builder/typescript#module-code).
4. It empties the output directory.
5. It bundles `src/module.ts`, and any other [bundled entry](/docs/guide/modules/module-builder/configuration#bundled-entries), with tsdown.
6. It transpiles `src/runtime/`, and any other [directory entry](/docs/guide/modules/module-builder/configuration#directory-entries), file by file.
7. It generates the declarations of every entry and runtime file, using the [module's `tsconfig.json`](/docs/guide/modules/module-builder/typescript).
8. It prints the [size of the output](/docs/guide/modules/module-builder/output#size-report).
9. It loads the built module to write `dist/module.json`, and writes `dist/types.d.mts`.
10. It checks the paths in `package.json` against the files it produced.

The build fails when a declaration can't be generated correctly. Other type errors are reported as warnings. See [TypeScript](/docs/guide/modules/module-builder/typescript#declarations) for both.

See [Build output](/docs/guide/modules/module-builder/output) for the files the build writes.

### Arguments

| Argument | Description |
|---|---|
| `ROOTDIR="."` | The module root. |

### Options

| Option | Default | Description |
|---|---|---|
| `--cwd=<directory>` | | The module root. Takes precedence over `ROOTDIR`. |
| `--outDir=<directory>` | | The output directory, relative to the module root. Takes precedence over `outDir` in the tsdown config, which defaults to `dist`. It's emptied before every build, so it must be inside the module. |
| `--sourcemap` | | Emit a source map next to every script. Takes precedence over `sourcemap` in the tsdown config. |

## `prepare`

```bash [Terminal]
npx nuxt-module-build prepare [ROOTDIR] [--cwd=<directory>]
```

Generates `.nuxt` in the module root. It runs `nuxt prepare` on the module root, as a Nuxt app with your module as its only module and auto-imports disabled. It writes nothing to `dist`.

Your module's `tsconfig.json` extends the `.nuxt/tsconfig.json` it generates. That gives your editor, your type check, and the declarations that the build generates the same types: `@nuxt/schema`, the `#app`, `#imports`, and `#build` aliases, and anything your module adds, such as its templates and server routes. See [TypeScript](/docs/guide/modules/module-builder/typescript).

It also writes `.nuxt/module-builder/types.d.mts`, which re-exports `src/module.ts` and adds the same [type augmentations](/docs/guide/modules/module-builder/project-structure#srcmodulets) as `dist/types.d.mts`. With [source exports](/docs/guide/modules/module-builder/develop-and-publish#source-exports), the root export's `types` condition points at it.

`prepare` loads `src/module.ts` with Node, and reads the options of `builder()` from `tsdown.config.ts`, which it loads with Node too. Module code therefore follows the rules in [Module code](/docs/guide/modules/module-builder/typescript#module-code). Until it does, `prepare` lists each problem and doesn't generate `.nuxt`. `prepare` fails when the tsdown config sets `cwd` to another directory. tsdown's hooks and plugins don't run for `prepare`.

Run `prepare` again after a change to anything the module registers for types: its options, templates, type declarations, or server routes.

### Arguments

| Argument | Description |
|---|---|
| `ROOTDIR="."` | The module root. |

### Options

| Option | Default | Description |
|---|---|---|
| `--cwd=<directory>` | | The module root. Takes precedence over `ROOTDIR`. |
